# Smart Queue Management System

A beginner-friendly Java Spring Boot project for a queue management system with:
- login page
- dashboard
- token generation
- queue management
- token history
- MySQL database persistence

This project is designed for a college demonstration and can be deployed as a real online website with a public HTTPS URL.

## Important note about deployment

This workspace contains the project files needed for online deployment. A real public URL is created only after you deploy it to a hosting platform using your own account. This project is not just a local app; it is configured for an online web deployment.

## Local development vs online deployment

### Local development
- Runs on your machine only.
- Uses local MySQL or a local DB URL.
- Good for testing and coding.

### Online deployment
- Runs on a public hosting service such as Render.
- Uses production environment variables.
- Generates a public HTTPS URL for demonstration.
- Keeps database storage on the deployed MySQL database.

## Features included

- Login screen
- Dashboard with queue summary
- Token generation form
- Service desk queue management
- Token history page
- MySQL-backed persistence through Spring Data JPA
- Secure environment variable configuration

## Project structure

- `src/main/java` — Java backend code
- `src/main/resources/templates` — Thymeleaf pages
- `src/main/resources/static/css` — styling
- `src/main/resources/application.properties` — base Spring Boot config
- `Dockerfile` — container build for deployment
- `render.yaml` — Render deployment config

## Environment variables

Set these before running or deploying the application:

- `DB_URL`
- `DB_USERNAME`
- `DB_PASSWORD`
- `APP_ADMIN_USERNAME`
- `APP_ADMIN_PASSWORD`
- `PORT`

Example values:

```bash
DB_URL=jdbc:mysql://localhost:3306/smart_queue?createDatabaseIfNotExist=true&useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=UTC
DB_USERNAME=smartqueue
DB_PASSWORD=your_secure_password
APP_ADMIN_USERNAME=admin
APP_ADMIN_PASSWORD=your_secure_admin_password
PORT=8080
```

Do not share real passwords in the project source. Use environment variables or your deployment dashboard.

## Run locally

1. Install Java 17 and Maven.
2. Create a MySQL database.
3. Set environment variables in a terminal or `.env` file.
4. Run:

```bash
mvn clean spring-boot:run
```

5. Open the browser at:

```text
http://localhost:8080/login
```

## Deploy online with Render (beginner-friendly GUI method)

1. Create a free Render account at https://render.com.
2. On the Render dashboard, click New and choose Web Service.
3. Connect your GitHub repository.
4. Select the project folder.
5. Render will read the included `render.yaml` configuration.
6. Create a MySQL database from the Render dashboard if it is not created automatically.
7. Set these environment variables in the Render web service dashboard:
   - `APP_ADMIN_USERNAME=admin`
   - `APP_ADMIN_PASSWORD=<choose a strong password>`
8. Keep `DB_URL`, `DB_USERNAME`, and `DB_PASSWORD` auto-filled by Render if using the database service from the configuration.
9. Click Deploy.
10. Wait until the deployment completes.
11. Render will give you a public HTTPS URL like:

```text
https://smart-queue-system.onrender.com/login
```

The exact URL will be generated by Render after deployment.

## Accessing the application after deployment

After successful deployment, open the URL that Render generates.

The login page will load directly at:

```text
https://<your-generated-render-url>/login
```

Then sign in with the admin username and admin password you configured in environment variables.

## Demo flow for your teacher

1. Open the deployed website URL.
2. Login using the admin credentials.
3. Open the Dashboard page.
4. Generate a token from the Token Generation page.
5. Go to Queue Management and serve the next customer.
6. Check the Token History page to confirm database persistence.
7. Explain that the application stores data in the hosted MySQL database and works online, not only on a local machine.

## Important deployment note

This repository is ready for online deployment, but the actual public website URL is created only when you deploy the project to Render or another hosting provider using your own account. The workspace itself does not automatically publish to the internet without credentials and a hosting service.

## Security reminder

- Never hardcode real passwords in source code.
- Store secrets in environment variables.
- Use the Render dashboard or a local `.env` file for credentials.
